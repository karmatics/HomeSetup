3. Machine Workspaces & Luno Nodes

Where Luno runs on each machine, filesystem layouts, and directory conventions.

Luno Installations & Directory Structures

Luno Workspace is designed to run locally on each machine. A Luno instance consists of the Node.js server (LunoServer.js) and client web interface. On the Linux box where you are currently running, the server serves the project files and provides API endpoints for disk writes (/api/save), server runners (<script data-file="RUN: SERVER">), and git checkpoints.

On the Mac and Windows machines, clone copies of the Luno repository or individual project checkouts can either run independent local Luno server instances (on port 3000) or open the web interface hosted by the Linux box across the LAN.

Directory Map Luno Root Paths per Machine
  • Linux Host: ~/Luno/ or ~/projects/ (subprojects: HomeSetup/, Library/)
  • Mac Machine: /Users/<user>/projects/
  • Windows Machine: C:\Users\<user>\projects\ or WSL /home/<user>/projects/

Machine-Specific Workloads & Strengths

Linux Workstation Role: Best suited for high-concurrency Node.js tasks, continuous background runners, database experiments, and server-side compilation.

Mac Role: Best for Safari web testing, iOS/macOS compilation, and design-heavy workflows. Windows Role: Best for gaming, DirectX graphics pipelines, Windows-only engineering tools, and secondary display monitors.

Task Distribution Optimal Task Distribution
  • Linux Host: Server hub, code generation testbench, continuous development.
  • Mac: Cross-browser verification, mobile device syncing, portable work.
  • Windows: CAD/BIM desktop tools, GPU render passes, PC hardware testing.
  • Phones: Mobile testing, two-handed gesture controller, instant QR scan testbeds.

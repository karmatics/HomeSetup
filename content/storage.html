The Roving Hard Drive & Cross-OS Mount Points

A core asset of this workstation setup is the high-capacity external hard drive. It can physically connect over USB-C / USB-A to any of the three main machines: the Linux host, the Mac, or the Windows workstation.

Because it moves between different operating systems, it is formatted with a universally readable filesystem (typically exFAT with consistent cluster sizing, or dual-partitioned with NTFS/ext4). This allows multi-gigabyte files, 3D asset libraries, model weights, and backup archives to move instantly without network bandwidth saturation.

To prevent scripts from breaking when the drive moves from one machine to another, we document the canonical mount paths for each operating system below.

Mount Directory Mount Paths by Operating System
  • Linux Host: /media/<user>/<VolumeName>/ or static mount /mnt/shared_drive/
  • Mac Workstation: /Volumes/<VolumeName>/
  • Windows Workstation: D:\ or E:\ (WSL2: /mnt/d/ or /mnt/e/)
  • Canonical Directory: <DriveRoot>/Workspace/ and <DriveRoot>/Backups/

Transfer Strategies: USB Thumb Migration vs. Live Luno HTTP

Physical Plug vs. Network Pull: When the drive is plugged into the Linux box, bulk transfers are local and blazing fast. If the drive is currently plugged into the Mac or Windows machine, the Linux host can still reach it across the LAN over an SSH/SMB share: rsync -avz --progress user@mac:/Volumes/<VolumeName>/ /local/target/.

This provides the best of both worlds: high-throughput physical portability when doing massive dump operations, plus network accessibility when the drive is attached to a remote machine across the room.

Transfer Recipes rsync & Luno Cross-Wire Sync Recipes
  • Pull from Mac to Linux: rsync -avz user@macbook:/Volumes/External/ ./destination/
  • Push from Linux to Windows: rsync -avz ./projects/ user@winbox:/mnt/d/Workspace/
  • Integrity Verification: Automated SHA256 checksum comparisons to guarantee byte-for-byte transfers.
